# 검정 파이프라인 (연구계획 v3, 7절 Step 1~4 + 게이트)

SKHYNIXUSDT(본주 퍼프)·SKHYUSDT(ADR 퍼프) 1분봉으로, 매 거래일 T0 이전 윈도우에서
**Step 1 (I(1) 검정) → Step 2 (헤지비율 4종) → Step 3 (스프레드 ADF·KSS 게이트) → Step 4 (모수·반감기)** 를
8개 변형(후보 4 × V1/V2)에 대해 돌리고 `daily_decision_log` 를 남긴다.
임계값·매매·비용(9·10절)은 아직 없다. 그래서 `decision` 은 비용 필터 전 단계 판정이다.

## 실행 (Windows cmd 기준)

```
pip install -r requirements.txt
cd stat_pipeline
python -m pytest -q tests                 :: 달력·통계량 검증 (10개)
python run_gate.py                        :: 실제 데이터, 계획서 규칙 그대로
python run_gate.py --ignore-coverage      :: 결측 10% 초과 윈도우도 통계량 계산 (결정은 DATA_BAD 유지)
python make_synthetic.py
python run_gate.py --synthetic            :: 정답을 아는 합성 쌍으로 작동 확인
python run_gate.py --start 2026-09-30 --end 2026-10-01 --B 99
python run_backtest.py                    :: 최신 게이트 결과로 매매 (5·9·10절)
python run_gate.py --synthetic && python run_backtest.py --synthetic   :: 합성 데이터로 매매까지 검증
```

원자료는 `data/raw/` 에 `SKHYNIXUSDT_YYYY-MM-DD.parquet`, `SKHYUSDT_YYYY-MM-DD.parquet` 로 둔다
(이름은 자유, 심볼은 파일 안의 `instrument_raw_symbol` 로 구분).
B=199 기준으로 1,440분 윈도우 하나에 약 15초, 2,880분 윈도우는 약 30초 걸린다(코어 1개).

원자료는 용량과 보안 때문에 깃에 올리지 않는다(.gitignore). 팀 공유 드라이브에서 받아 아래에 넣는다.

- `data/raw_orderbook/` : order_book parquet (있으면 분 중간가·호가 VWAP 체결을 자동 사용)
- `data/raw_funding/` : funding_rate parquet (정산 시각표·펀딩 점검). 파일 이름은 `funding_<심볼>_<날짜>.parquet` 권장 (두 종목 같은 날짜 파일이 덮어써지지 않게). 내용은 심볼 컬럼으로 구분하므로 이름은 자유.
  - 확인된 정산 주기: 본주 SKHYNIXUSDT 4시간(KST 01·05·09·13·17·21시), ADR SKHYUSDT 8시간(KST 01·09·17시). 레코드의 funding_interval_hours 값은 두 종목 모두 8로 찍혀 있어 믿지 않고 실제 정산 간격으로 추정함.

게이트를 통과하지 못한 날도 같은 규칙으로 **가상 매매**(is_real=False)를 계산해 둔다 (13절 게이트 정보력 검정용).

## ESTAR 임계값 (KSS 버전, 2026-10-04)
- 모형: `Δz_t = phi z_{t-1} (1 - exp(-gamma z_{t-1}^2)) + Σ c_j Δz_{t-j} + e_t` 를 윈도우 z (연속 구간 안의 차분만) 에 적합.
  gamma 로그 격자 + OLS (profile NLS), Δz 래그 수는 BIC (0..10). 경로는 적합 재귀 + 잔차 복원추출, 시작값은 윈도우 실제 값.
- 안정 조건: |z| <= 10 에서 1분 복귀율이 (0, 2). 시뮬레이션 경로의 1% 넘게 |z| > 25 로 가면 선형으로 대체.
- 실제 데이터 (7일 x 4후보): 28건 모두 적합 성공. 6일은 gamma 가 아주 작아 **3차항(phi*gamma = KSS delta) 만 식별** -> 
  사실상 `Δz = delta z^3`. 10/01 만 gamma 약 26 (전이가 |z|~0.2 에서 끝남 -> 거의 선형).
  |z|=2 에서 1분 복귀율 0.009~0.028 (반감기로 치면 약 25~75분).
- 선형과 비교: 진입선 같거나 0.25 높음, 손절 5 -> 4 로 낮아지는 날이 많음. 가상 매매 손익은 거의 같음 (후보별 ±3달러).
  ESTAR 경로는 0 근처에서 랜덤워크라 오래 머물러 기대 펀딩이 선형보다 큼 (하루 0.4~0.9달러 vs ±0.05).

## 임계값 시뮬레이션 보정 (2026-10-04)
- 문제: 시뮬레이션 기대 수익(하루 최대 110달러)이 가상 매매 실현치(하루 몇 달러)보다 훨씬 컸다. 비용 필터가 작동하지 않음.
- 원인 진단: 윈도우 모수로 계산한 **다음 날 z 의 평균이 0 이 아님** (-1.8 ~ +3.1, 표준편차 0.24~2.0). 모형은 z 가 0 으로
  돌아온다고 가정하지만 실제로는 스프레드 수준이 다음 날 옮겨 가 있다. 모형 형태(선형/ESTAR)보다 이 수준 이동이 결정적.
- 대응: 두 버전 모두 수준 이동 tau 반영. tau = T0 이전 같은 후보 거래일들의 "그날 z 평균" RMS (최근 10일, 3일 미만이면 2.0).
  거래일 d-1 은 d 의 T0 직전에 끝나므로 룩어헤드 없음. 실측 tau 1.7~2.1.
- 블록 부트스트랩(윈도우 실제 z 재표본)도 시험했으나 **기본으로 쓰지 않음**: 블록이 바뀔 때마다 z 가 윈도우 분포에서 새로
  뽑혀 0 쪽으로 "리셋"되는 가짜 평균회귀가 생겨 기대 수익이 오히려 더 부풀려짐 (OLS 기준, 평균 블록 120분: 모형 대비 2~3배,
  1440분: 1.5~2배). 옵션으로만 남김 (`linear_path_method`, `block_len_min`).
- 결과 (가상 매매, 4후보 합계): 기대 vs 실현 — ADF 345 vs 27달러, KSS 272 vs 54달러 (보정 전 ADF 약 1,070 vs 13달러).
  여전히 낙관적이지만 기대 순수익 <= 0 인 날이 생겨 비용 필터가 작동하기 시작함 (ADF 5건, KSS 4건).
  일부 차이는 데이터 공백 (9/23 213분, 9/24·9/28 0분만 있음 -> 시뮬레이션은 하루 전체 가정).
- 남은 점: 보정 후 진입선이 격자 상한 3.0 에 붙는 경우가 많음 (ADF 11/28, KSS 9/28) = 사실상 "거래하지 말라" 신호.
- 점검표: `reports/threshold_calibration_<run_id>.csv` (기대 거래 수·손익 vs 가상 매매 실현), 실행 끝에 합계 출력.
- 격자 확장: 진입 0.75, 청산 -1.0·-0.75 추가 (이전엔 청산선이 28건 모두 하한 -0.5).

## 펀딩을 임계값 최적화에 넣기 (2026-10-04)
- 예상 펀딩률 = T0 이전에 정산된 최근 6건 평균 (부호 유지, `[funding] forecast_*`). 기록 없으면 0.
- 시뮬레이션에서 정산 분에 포지션이 있으면 롱/숏 스프레드별 펀딩을 손익에서 뺀다 (`thresholds.funding_z`).
- 표본 펀딩률이 거의 0 이라 선형 임계값은 바뀌지 않음 (기대 펀딩 하루 ±0.05달러). `forecast_method="abs"` 면 방향과 무관하게 비용으로 보는 보수적 가정.

## 판정 순서 (`no_trade_reason`)

`DATA_BAD`(ADR 없음 또는 결측 >10%) → `HOLIDAY_RULE`(쓸 정상 블록 없음) → `STEP1_UNDETERMINED` →
`BAD_HEDGE`(b ≤ 0) → `GATE_FAIL`(ADF·KSS 모두 비기각) → `HALFLIFE_FILTER`(반감기 > 120분) → `TRADE`.
`STEP1_UNDETERMINED`, `HALFLIFE_FILTER` 는 계획서 사유 목록에 없어 새로 붙인 이름이다.

## 계획서를 코드로 옮기며 정한 것 (연구자 확인 필요)

1. **Step 1 은 거래일×버전마다** 한 번 (V1·V2 윈도우가 달라서). 4개 후보가 공유한다.
2. **결측 분은 버리고 이어 붙인다** (두 심볼 모두 있는 분만). 10% 이하 결측일 때만 판정에 쓰이므로 영향은 작다.
3. **RMAIC** 는 Cavaliere-Phillips-Smeekes-Taylor(2015) 원논문의 RSMAIC 그대로 구현 (변동성 재척도 후 MAIC, 커널 h=0.1).
4. **KSS 래그** 는 같은 시리즈의 선형 ADF 에서 고른 k 를 그대로 쓴다.
5. **TLS** 는 평균 제거 후 직교회귀. TLS 의 b 신뢰구간(A-4 비귀무 부트스트랩)은 아직 없다(NaN).
6. **화요일 V2** 는 일·월 블록이 연속 정상 블록이 아니라서 항상 V1 으로 대체된다 (6절 규칙 그대로).
7. **후보 1(OLS)** 게이트 p 는 MacKinnon EG 표, 부트스트랩 p 는 `adf_p_boot` 에 대조용으로 기록.

### RSMAIC (Cavaliere, Phillips, Smeekes & Taylor 2015, Econometric Reviews 34(4), 식 5-7)
1) 상수 제거 시리즈에 kmax 차 ADF 회귀 -> 잔차, 2) 잔차 제곱을 가우시안 커널(h=0.1)로 평활해 변동성 경로 추정,
3) 차분을 변동성으로 나눠 누적한 재척도 시리즈 생성, 4) 그 시리즈에 MAIC 적용. 선택은 OLS 추세제거 데이터에서 (Perron-Qu 2007).
이전 구현(tau 를 이분산 보정형으로 바꾼 것)은 원논문과 달라 폐기. 확인: 변동성이 4배로 뛰는 랜덤워크(참 래그 0)에서 MAIC 10, RSMAIC 0.

### 오더북 (src/orderbook.py)
depth@100ms 변경분만 있고 시작 스냅샷이 없어 빈 호가창에서 재구성. 시퀀스가 끊기면 새로 시작, 60초 워밍업.
검증(SKHYUSDT 09-18, 19:28~23:52): 스프레드 1틱(0.54bp), 분봉 종가의 82% 가 재구성 bid~ask 안, 나머지도 1~3틱 이내.
현재 오더북은 ADR 4.4시간뿐이라 검정에 쓰인 구간과 겹치지 않음 (mid_frac = 0).
실제 호가 잡음은 작다(종가-중간가 중앙값 0.27bp, 반 틱). 반감기 편향은 합성 데이터에서 본 것보다 작다:
실제 데이터 ARMA 반감기가 AR(1) 보다 6~60% 길다.

## 알려진 문제

- **게이트 오통과 11~13%** (ADF 또는 KSS 규칙 + KSS 부트스트랩 과대 크기). 2026-10-03 결정으로 규칙은 유지.
- **Step 1 이 박스권 가격을 걸러내지 못한다** (위 시뮬레이션). 실질적인 걸러내기는 Step 3 게이트와 반감기 필터가 한다.
- **반감기:** AR(1) 은 호가 잡음에 과소추정 -> ARMA(1,1) 로 보정 (합성: 참값 45분, AR(1) 25.5 -> ARMA 42.5).
- **결측 기준 해제 후:** 공백이 있는 창은 관측된 분만 이어 붙여 검정한다. 수 시간 공백을 한 분으로 취급하는 셈이라, 공백이 큰 창의 결과는 `missing_frac_paired` 와 함께 해석할 것.
- **수신 지연:** 07:59 분봉은 T0 이후 0.1~3초에 수신된다. 감사에서 경고로 보고.
